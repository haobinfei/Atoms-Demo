# 0017. 控制台化前端布局

日期：2026-10-15
状态：已接受

## 背景

产品前端原为"顶部横向导航 + 居中内容流"的结构。团队决定将登录后的界面改造为
maitokens.top/dashboard 那类后台控制台风格：左侧固定导航、顶部工具栏、浅色内容区、
更高的信息密度。

改造前需先钉死三个有真实取舍的决策：主题策略、工作台布局范围、项目总览形态。

## 决策

1. **布局控制台化，颜色跟随现有明暗主题。**
   侧栏/顶栏/卡片等结构改为控制台式，但所有颜色仍走现有 CSS 变量与
   `theme.ts` 的明暗切换；不把界面固定为浅色，也不更换品牌主色（保持橙色）。
   理由：主题能力是已有个人偏好功能，e2e 与用户习惯都依赖它；换主色是品牌决策，
   不应搭车在布局改造里做。

2. **控制台外壳只覆盖列表/管理页；项目工作台保持全屏。**
   侧栏 + 顶栏常驻于项目总览、工作区列表、成员、账户、平台管理五类页面。
   进入某个项目的工作台（`Workspace.tsx`）时收起侧栏，保留现有"对话 + 预览"
   全屏左右分栏。理由：工作台的双栏已经需要最大空间，再嵌侧栏会压缩预览。

3. **项目总览保留卡片网格 + 实时预览封面，不改表格。**
   控制台化只换容器与信息密度，不把卡片流换成表格列表。理由：实时预览封面
   （ADR-0014 定义其可用性信号）是产品差异化能力，表格化等于移除它。

4. **总览统计卡只做前端可算的部分。**
   若加统计概览，只对 `listSessions` 结果做前端聚合（总数、构建中、完成、失败），
   不新增后端统计接口，不展示无数据来源的假指标。

## 后果

- `App.tsx` 的登录后外壳改为侧栏结构；`Home.tsx` 新建项目首屏（居中输入框）
  与登录页不在本轮范围内。
- 实施前须先提交工作区中已存在的未提交改动，避免样式改写与进行中的
  手改文件功能（OPT-502，见 ADR-0016 尾注）混在同一批 diff 里。
- 样式改写直接落在 `styles.css` 对应段落，不采用末尾覆盖层。
