# ADR-0009: 自有账户与单层工作区租户

平台改为自行提供邮箱注册、验证、密码登录和重置，不再依赖 AuthSphere OIDC。账户可以加入多个工作区；每个新账户获得个人工作区，已验证账户可创建团队工作区。项目归工作区所有，创建者离开不影响归属。工作区先设所有者和编辑者两种角色；独立的平台管理员可处理跨工作区的账户与归属问题，但不因管理员身份获得项目内容读取权。

这一决定取代 ADR-0005 的身份认证及按 AuthSphere `sub` 归属会话的方案，使注册、成员和工作区生命周期由平台统一管理。代价是平台自行承担密码与账户安全维护；旧 AuthSphere 数据不迁移到新账户体系，以避免无法可靠核验的身份映射，旧项目不会自动出现在新账户中。预览与发布访问边界另见 ADR-0010。

注册、验证、邀请和密码重置邮件由平台通过 SMTP 发出。邮箱验证完成前，账户不能进入工作区或使用项目功能。旧数据及依赖它的公开链接一并下线，不承诺保留旧应用访问。账户停用应撤销登录能力并保留工作区数据；永久删除前须先解决其所有者身份及工作区归属，不能使工作区失去最后一位所有者。

个人工作区仅供注册账户本人使用，不添加成员，也不转换为团队工作区；协作须新建团队工作区。平台管理员身份只通过服务端受控配置授予，不允许工作区所有者自行授予。跨工作区管理操作应记录操作者、对象、时间和原因；管理员仍不能凭此身份读取项目内容。

账户可自行申请永久删除，但须先交接其独占所有权的团队工作区；删除账户时，其个人工作区及已发布应用一并下线。首版不提供账户或团队工作区删除后的恢复入口，删除前须二次确认并明确告知数据与公开链接不可恢复。登录邮箱首版不支持自行更换，以免邮箱身份与待处理邀请出现歧义。唯一所有者的账户停用或无法访问时，平台管理员可在填写原因并留存审计记录后指定新的所有者，不因此获得项目内容读取权。

账户、成员、邀请、登录会话与管理审计在所有环境都以 Postgres 持久化；本地 Compose 也提供 Postgres，生产数据库迁移遵循现有 gitops 部署约定。生产邮件通过受控配置连接 163 邮箱 SMTP，授权码只由 Secret 注入，不写入仓库或日志；本地开发通过邮件捕获服务验证完整流程。

一个账户可在多个工作区之间切换；首次登录进入个人工作区，后续登录恢复上次使用的工作区。首版平台管理员权限限于查看账户及成员关系、停用或恢复账户、处理所有者救援和查看审计记录；不能读取项目内容，也不能代替成员发布或删除项目。首版不提供多因素认证，但注册、登录和密码重置须限流，并避免错误信息暴露邮箱是否已注册。
