# 移除模板兜底：模型失败必须显式报错

生产生成链不再以内置 `TemplateProvider` 收尾。DeepSeek、Kimi、本地 gemma 之间仍可
按配置逐级容错，但全部模型不可用、输出无法解析或文件校验失败时，回合直接失败并把
具体错误写入事件流，不再生成固定的模板应用。

原因：模板只能识别少量类别、名称和颜色，无法执行“增加三篇文章”这类后续内容需求。
继续把模板作为成功产物会掩盖模型故障，并让用户看到一个看似成功、实际未执行最新
要求的旧应用。这个误导比“当前没有生成结果”更糟。

`TemplateProvider` 仅保留为测试夹具，用于不依赖网络的确定性测试；它不出现在
`ChainFromEnv`、竞赛参赛者或评分兜底的生产路径中。

这取代 ADR-0002 中“模板保证任何环境必有产物可预览”的决策；ADR-0002 保留为历史记录。

_Avoid_：模型失败后返回固定模板却显示“生成成功”；把模板作为竞赛参赛者；为了演示
不断链而隐藏真实生成错误。
