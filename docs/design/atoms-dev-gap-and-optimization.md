## 3. 六维差距与优化项

### 3.1 注册登录（3/5）

现状：认证链路完整（注册、验证、登录、忘记/重置密码、会话吊销）。缺口在**进入产品的顺畅度**与**首次使用引导**。

- `OPT-101` 表单体验：密码显隐切换、输入时密码规则提示（当前仅靠 `minLength=12`）、字段级错误提示、验证邮件重发倒计时。证据：`web/src/Auth.tsx:122-129`。
- `OPT-102` 登录后回到原位置：会话过期跳登录后，重新登录应回到原项目而非首页。证据：`web/src/api.ts:211`（`redirectToLogin` 直接 `location.href = '/'`）。
- `OPT-103` 注册后引导：注册完成提供示例需求或模板，帮助用户产出第一个应用。
- `OPT-104` 第三方登录（OAuth）：Atoms 支持邮箱密码与 Google 等。**本轮不做**（§8.1 依赖政策）。

### 3.2 Agent 交互（3/5）

现状：多 Agent 人设、阶段事件、文件事件、追问均已实现。缺口在**过程可读性**与**用户控制权**。

- `OPT-201` 时间线卡片化：当前事件逐条平铺，同 Agent 连续事件用表头合并。改为按**回合（Turn）**分组，显示"本轮目标 → 执行过程 → 交付结果"。证据：`web/src/Timeline.tsx:24-63`。
- `OPT-202` 文件事件折叠：`file` 事件逐条展示路径，改为"修改了 N 个文件"可展开。证据：`web/src/Timeline.tsx:52`。
- `OPT-203` 回合完成摘要：流水线已写入回合摘要消息，前端未突出展示。证据：`internal/pipeline/pipeline.go:224`（`appendTurnSummary`）。
- `OPT-204` 失败可诊断：当前 `error` 事件只展示 `err.Error()`，缺少失败阶段与可执行建议。证据：`internal/pipeline/pipeline.go:176`。
- `OPT-205` 追问排队：构建中输入框被禁用，用户无法预先输入下一条。Atoms 支持排队并可编辑/删除/重排。**已定：纯前端内存队列**（§8.1），构建中可继续输入，回合结束后自动发送；刷新丢失，可接受。
- `OPT-206` 取消正在执行的回合：无任何后端取消路径。**已定：术语「取消回合（Cancel Turn）」，实现为持久化标志**（§8.1）。语义见 §8.1 与 `docs/adr/0013`。
- `OPT-207` 用户主动重试失败回合：现有"重跑"只有崩溃恢复（`recovery`）与 Provider 降级，二者都不是用户操作。证据：`docs/adr/0007`、`internal/provider/chain.go:31`。

### 3.3 数据持久化（3/5）

现状：Postgres 为事实源，会话/事件/消息/发布记录已落库；事件有跨副本分发与断线重放。缺口在**可靠性可验证**与**源码/产物持久化边界**。

- `OPT-301` 可靠性验收清单：刷新、断网重连、服务重启三种情况下，项目列表、消息历史、构建状态必须一致。**这是"提分证据"而非新功能。**
- `OPT-302` 源码持久化边界：数据库存元数据，生成源码仍在 workspace；多副本需共享 RWX 存储。需核验正式环境实际配置（COS / Redis / 共享卷）。证据：`README.md:60`、`cmd/server/main.go:112`。
- `OPT-303` 生成应用的业务数据持久化：平台保存项目 ≠ 生成应用保存业务数据，演示时须分别验证（例：待办应用写入一条数据 → 刷新 → 重新登录 → 数据仍在）。
- `OPT-304` 构建历史保留与 GC：当前旧 build 无限累积且不可枚举。若要做版本能力，需先加 List 与清理策略。**本轮范围外**；启用前需先解决 §5 第 1 项的「版本」定名。

### 3.4 页面美观度（2/5）

现状：上一轮 P0 已落地设计 token、统一组件类、深色设计系统、认证页品牌栏、账户菜单、项目卡片。缺口在**用户停留最久的工作台**。

- `OPT-401` 工作台布局：聊天与预览比例固定，改为**固定比例 + 可折叠**（放大预览 / 放大对话切换）。**已定**（§8.1）；不做拖拽分栏与宽度持久化。
- `OPT-402` 视觉层级：统一 Agent 消息、工具活动、完成摘要、失败状态的层级，替换当前平铺样式。
- `OPT-403` 输入体验：输入框改多行，`Enter` 发送 / `Shift+Enter` 换行。证据：`web/src/Workspace.tsx:183`（当前为单行 `input`）。
- `OPT-404` 状态反馈：补齐加载、空、断线、失败四态的明确反馈。
- `OPT-405` 项目封面改用截图缩略图：当前每张 ready 卡片加载一个真实 iframe，列表变大后并发运行多个应用。**已定：本轮不做缩略图，保留实时 iframe 并加并发上限**（§8.1）。方案背景见 `docs/design/ui-refresh-p0.md` §4。

### 3.5 代码管理（3/5）

现状：文件列表、源码读取、复制、ZIP 导出已实现。缺口在**编辑**与**改动可追溯**。**本轮不做。**

- `OPT-501` 文件树增强：文件名搜索、语法高亮、行号。当前为纯文本列表 + `<pre>`。证据：`web/src/FilesDrawer.tsx:74-81`。
- `OPT-502` 代码编辑与保存：需要后端写入路由（当前只有 list/read/export，**没有写入接口**）。证据：`internal/server/server.go:365-367`。
- `OPT-503` 改动对比（Diff）：Atoms 支持逐文件 Diff。需要保存编辑前后版本。
- `OPT-504` 版本历史与恢复：见 §3.6 与 §5 第 1 项，成本最高。
- `OPT-505` GitHub 同步：Atoms 支持导出并同步到 GitHub。**本轮不做**（第 5 项不在本轮范围）。

### 3.6 产物预览（3/5）

现状：桌面/移动视口、刷新、新标签页、竞赛候选回看均已实现。缺口在**稳定性**与**失败可诊断**。

- `OPT-601` 修复预览周期性重载：见 §4 BUG-1。**优先级最高。**
- `OPT-602` 修复竞赛候选预览的"打开"链接：见 §4 BUG-2。
- `OPT-603` 预览加载与失败状态：当前 iframe 无 loading/error 反馈。
- `OPT-604` 预览可用性检测：`iframe.onError` 无法识别跨文档 HTTP 错误页。**已定：服务端派生标志 `previewReady` + 前端加载超时兜底**（§8.1、`docs/adr/0014`）。
- `OPT-605` 草稿版与已发布版标识：让用户分清正在看的是预览还是线上版本。
- `OPT-606` 生成应用与平台的权限隔离：`/app` 与 SPA 同源，README 明确当前同源路由**不是**已验收的生产权限边界。证据：`README.md:94`、`docs/adr/0010`。**本轮范围外。**

## 4. 可直接修复的确定性缺陷

这四条是代码级事实，不依赖 §8 的任何决策，可独立修复。

### BUG-1 预览周期性重载（高优先级）

`web/src/Workspace.tsx:82-98` 的 15 秒对账在 `status === 'ready'` 时仍执行 `setBuiltAt(new Date().toISOString())`（L94）。`builtAt` 是 `Preview` 的 iframe key 组成部分（`web/src/Preview.tsx:48`），因此**只要会话处于 ready，预览每 15 秒被强制重载一次，用户无法在预览里连续操作**。

修复方向：只在构建版本实际变化时更新 `builtAt`（例如比较构建标识或 `updatedAt`），对账只用于补齐事件与状态。

### BUG-2 竞赛候选预览的新标签页链接错误

`web/src/Preview.tsx:41` 的"打开"链接固定为 `/app/${sessionId}/`。当 `src` 被指定为竞赛候选版本（`web/src/Workspace.tsx:231` 传入 `/app/{id}/contest/{provider}/`）时，新标签页打开的仍是正式版而非当前正在看的候选版本。

修复方向：`打开` 链接与 iframe 使用同一个 `src`。

### BUG-3 发布等待超时

`web/src/api.ts:230-244` 的 `publishSession` 轮询 15 秒后抛错。发布实际由 Worker 异步执行（`internal/server/server.go` 的 publish 任务），构建较慢时会稳定超时，前端只显示"操作失败，请稍后重试"，用户无法判断是否已成功。

修复方向：改为订阅已有的事件流或延长轮询并展示进行中状态，不要用固定超时判定失败。

### BUG-4 iframe 错误检测不可靠

`web/src/Dashboard.tsx:45` 依赖 `iframe.onError` 触发降级封面。跨文档的 HTTP 错误页（如 404/502 返回 HTML）不会触发 `onError`，因此降级逻辑会漏判。

修复方向：已定为由服务端派生标志 `previewReady` 判定（由 `status` 与 `current.json` 计算，不落库），前端仅在为真时渲染 iframe，并叠加加载超时兜底。详见 §8.1 与 `docs/adr/0014`。**注意该标志只是渲染提示，不得当作权限判据。**

## 5. 术语冲突

`CONTEXT.md` 是本仓库的术语表，`docs/agents/domain.md` 要求输出必须使用其中词汇。以下三处曾存在冲突，现状如下：

1. **"版本"被三种概念混用**（**未定名**）：`发布（Publish）` 的版本号（`session.go:85` 的 `Version`）、内部的 `buildID`（`artifact/store.go:344`）、以及竞赛归档版本（`contest/<provider>`）。`CONTEXT.md` 里 `发布` 写着"发布记录是版本事实"，但发布记录**不含 buildID**，三者当前无法互相定位。**处置：本轮不定名，但新增文案与字段命名中避免使用"版本"一词**（见 §8.1），等做版本历史时再定名并写 ADR。
2. **用户态"停止任务"与 `任务（Job）` 撞名**（**已解决**）：`CONTEXT.md` 明确"任务"专指调度单位（`turn`/`contest`/`publish`），并注明"勿与「回合」混用"。**已定名为「取消回合（Cancel Turn）」**，不得使用"停止任务""终止任务"等说法（见 §8.1）。
3. **缩略图与 `预览` 的边界**（**本轮不触发**）：`CONTEXT.md` 定义 `预览` 为"工作区成员检查未发布应用的运行结果的访问方式；非成员不能访问"。未发布应用的缩略图属于该边界内，**不得作为公开资源**；且 `项目（Project）` 被定义为列表项展示层，加 `thumbnailUrl` 是对该模型的变更，需同步更新术语表。**处置：本轮不做缩略图**（见 §8.1），该冲突暂不触发；未来若启用，必须先解决本项。

### 8.1 已决策（2026-10-13）

以下十二条是**边界**，执行时不得违反。

| 项 | 决策 | 对执行的影响 |
| --- | --- | --- |
| 验收场景 | **面试现场演示**（10–20 分钟走查） | 优先级按"演示停留时长 × 暴露度"排序；但**演示路径上每个能力必须真实可跑，不做假数据、不做只改文案的假按钮** |
| 交付边界 | **前端 + 后端小改**：可加路由与状态转移，**不改数据模型、不改已有表结构** | 解锁第 3 批；排除需要数据模型变更的方案（给 `Publish`/`Event` 补 buildID、排队消息落库等） |
| 本轮范围 | **只做第 2、4、6 项**（Agent 交互、页面美观度、产物预览） | 代码管理（第 5 项）、注册登录改造（第 1 项）不在本轮；第 4、5 批不做 |
| 依赖政策 | 允许**前端纯 JS 依赖**；**拒绝后端 headless chromium**；**OAuth 与浅色主题本轮不做** | 缩略图若做只能走前端截屏；本轮已决定不做（见下） |
| 项目封面形态 | **保留实时 iframe**，加并发上限（只为可视区域内的卡片渲染，离开视口卸载）+ 失败降级；**本轮不做截图缩略图** | 排除 `OPT-405` 的截屏上传路线；`OPT-604` 不能再依赖缩略图接口作为探针 |
| 取消回合 | 术语「**取消回合（Cancel Turn）**」；语义 = 中止本回合生成、保留上一版产物、会话回到 `ready`、**追加**一条取消事件（不删除已有事件）；**实现为持久化标志**，不用进程内 cancel | 决定 `OPT-206`；在 `replicas > 1` 与 Pod 重启下仍然正确；见 `docs/adr/0013` |
| 追问排队 | **纯前端内存队列**：构建中可继续输入，本回合结束后自动发送；刷新丢失 | 决定 `OPT-205`；不改数据模型 |
| 演示黄金路径 | **主线 + 可靠性亮点**：登录 → 生成 → 追问修改 → 预览 → 发布，并包含"构建中刷新页面，验证状态与消息不丢" | §6.1 验收脚本按此细化；为第 3 项（数据持久化）提供直接证据 |
| 「版本」定名 | 本轮**不定名**；新增文案与字段命名中**避免使用"版本"一词** | 见 §5 第 1 项 |
| 预览可用性判定 | **服务端派生标志** `previewReady`（由 `status` 与 `current.json` 计算，**不落库**）+ 前端加载超时兜底；**不用 `iframe.onError` 作判据**，也不把它当权限判据 | 决定 `OPT-604` / BUG-4；见 `docs/adr/0014` |
| 取消与排队的交叉语义 | 取消回合后，排队消息**保留待发**，由用户确认后再发送，不自动执行 | 决定 `OPT-205` + `OPT-206` 的交叉行为；见 `docs/adr/0013` |
| 工作台分栏形态 | **固定比例 + 可折叠**（放大预览 / 放大对话切换）；不做拖拽分栏与宽度持久化 | 决定 `OPT-401` |

补充事实（执行时须知）：回合是**原子**的——`pipeline.go:295-318` 的 `writeFiles` 由 `Run` 在生成全部完成后才调用，因此中止本回合不会留下半成品文件，上一版产物自然保留；但事件是实时持久化的，时间线会留下已发生的阶段。
